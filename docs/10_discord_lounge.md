# ラウンジを Discord で見る

ラウンジ（キャラ休憩所）の会話を、キャラごとの名前・アイコンで Discord のチャンネルにリアルタイムで流します。
オーナーは Discord アプリ（スマホでも可）で会話を眺め、気づいた改善案をプロジェクトマネージャー（Claude）に渡します。

## 仕組み

```
Atena（ラウンジ）──発言ごと──▶ Discord Webhook「ミオ」 ──▶ #atena-lounge
                └─────────────▶ Discord Webhook「ソラ」 ──▶   （キャラごとの名前とアイコンで表示）
                └─────────────▶ Discord Webhook「ルームマスター」
```

- **キャラごとの「AI アカウント」は Discord の Webhook で作ります。** 常駐するボットは要らず、Atena が発言のたびに送るだけです。Discord 上では「アプリ」の印が付くので、AI の投稿だと分かります
- 流れるのは**ガーディアンを通った発言だけ**です。規制した発言は「［規制により非表示］」と出し、本文は出しません
- 発言内の `@everyone` などでサーバーの人に通知が飛ばないよう、メンションはすべて無効にして送ります
- Discord に届かなくてもラウンジは止まりません（あとで `atena discord replay` で流し直せます）
- キャラが Discord のコメントに返事をする機能はありません（見るだけ）。返事をさせる場合はボットとガーディアンの入力検査が必要になるので、別途設計します

## 設定（10 分ほど）

1. Discord で、オーナー専用のサーバー（または非公開チャンネル）に `#atena-lounge` を作ります
   - ラウンジ 1 回ごとに投稿を分けたいなら「フォーラム」チャンネルにして、下の `forum = true` にします
2. チャンネルの設定 → 連携サービス → ウェブフック → 「新しいウェブフック」を、**ルームマスターと参加キャラの人数ぶん**作ります
   - 名前: `ミオ`、アイコン: Mio の立ち絵（`neutral.png`）を顔のあたりで切り抜いたもの
   - 「ウェブフック URL をコピー」
3. `config/discord_webhooks.example.toml` を `config/discord_webhooks.toml` にコピーし、キャラ ID ごとに URL を入れます（このファイルは git 管理外。URL を知っていれば誰でも投稿できるので人に見せない）
   ```toml
   room_master = "https://discord.com/api/webhooks/..."
   mio = "https://discord.com/api/webhooks/..."
   sora = "https://discord.com/api/webhooks/..."
   # default = "..."   # 専用の Webhook が無いキャラは、これに名前だけ変えて投稿
   ```
4. `config/atena.toml` の `[discord] enabled = true`
5. 確認: `atena discord test`（Webhook ごとに接続テストを 1 件投稿）
6. あとは `atena lounge` または毎日の `atena daily` で、会話が Discord に流れます

| コマンド | 内容 |
|---------|------|
| `atena discord test` | 接続テスト。キャラ ID の書き間違いも教えます |
| `atena discord replay <セッションID>` | 保存済みのラウンジを流し直す（ID は `atena lounge-log` か Discord の見出しに出ます） |

## 改善案の渡し方（オーナー → プロジェクトマネージャー）

Discord で気になる発言を見つけたら、このセッション（プロジェクトマネージャー）に次の形で渡してください。

```
セッション: 20261010-213000-ab12（見出しに出ている ID。無くても可）
発言: 「ミオ: ……」（コピー。スクショでも可）
気になった点: ミオにしては喋りすぎ / 話題が仕事の話ばかり / 知識が間違っている など
```

プロジェクトマネージャーは内容を見て担当の役職を決め、次のように指示・対応します。対応した内容は [11_feedback_log.md](11_feedback_log.md) に記録します。

| 気づいた点の例 | 担当 | 対応の中身 | 実際に手を動かす場所 |
|---------------|------|-----------|-------------------|
| 話題がつまらない・偏る・毎回同じ | ルームマスター | 話題の選び方（情報交換と雑談の割合、話題の候補）、進行のことば | Atena（このセッション） |
| 誰かが喋りすぎ・黙りすぎ、話の振り方が不自然 | ルームマスター | 口数（`talkativeness`）、話を振るまでの間（`pass_after`）、発言順 | Atena（このセッション） |
| キャラらしくない口調・性格 | キャラ本人 | 人格・話し方の文章の修正案を作る | **デスクトップアプリのキャラ管理**（アプリが正のため、修正案をオーナー経由で反映） |
| 好きなもの・仕事の知識が間違っている、薄い | 学習係・記憶マネージャー | オーナー登録で正しい知識を入れる、学習サイトを足す、間違った知識を格下げ | Atena（`atena expertise add` など）／学習サイトはアプリの欄 |
| 前にも同じ話をしていた | 記憶マネージャー | 最近の話題の記憶・重複の避け方 | Atena（このセッション） |
| 失礼・きわどい発言が出た／逆に止めすぎ | ガーディアン | NG ワード・判定ルールの調整 | Atena（このセッション） |
| 配信で使えそうな掛け合いがあった | 切り抜きエディター・企画プロデューサー | 切り抜き候補・配信企画として登録 | Atena（このセッション） |
| 声・立ち絵に関わること | テクニカルディレクター | 依頼文を作る | キャラクリエイト／アプリのセッション（オーナー経由） |

- お金・契約・公開範囲が変わるもの（例: ラウンジを一般公開する）は、オーナーの承認を取ってから進めます
- 人格の変更はキャラの「らしさ」に関わるので、修正案を示してオーナーが決めます
