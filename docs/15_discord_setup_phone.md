# Discord の準備（スマホだけで）

サーバーを立てたあとの手順です。所要 15 分ほど。iPhone の Discord アプリを想定しています（Android もほぼ同じ）。

## 完成形

```
あなたのサーバー（自分だけ。だれも招待しない）
└ 📁 Atena
   ├ #ラウンジ     … キャラ同士の会話が流れる（ルームマスター・Sora・Mio の Webhook）
   └ #運営報告     … 毎朝の運営報告と、ラウンジの振り返り（プロジェクトマネージャーの Webhook）
```

- 会話と運営の連絡を分けると読みやすくなります。分けなくても動きます（その場合はマネージャーの Webhook を作らない）
- 「ラウンジ 1 回 = 1 投稿」にまとめたい場合は、#ラウンジ を**フォーラム**で作ります（Atena 側は `forum = true`）。迷ったら普通のテキストチャンネルで大丈夫です

## 1. チャンネルを作る

1. サーバー名をタップ → 「チャンネルを作成」
2. 種類「テキスト」、名前 `ラウンジ` → 作成
3. もう一度「チャンネルを作成」→ テキスト、名前 `運営報告` → 作成
4. （任意）カテゴリ「Atena」を作ってまとめる

サーバーは作った人しか入れません。**招待リンクは作らない・人を招待しない**でください（招待＝公開範囲の変更になります）。

## 2. Webhook（キャラのアカウント）を作る

作るもの（Webhook の名前は Discord に表示される名前、「キー」はあとで Atena の設定に書く名前）:

| チャンネル | Webhook の名前 | アイコン | キー |
|-----------|---------------|---------|------|
| #ラウンジ | ルームマスター | 好きな画像（例: ソファや鍵のマーク） | `room_master` |
| #ラウンジ | Sora | Sora の立ち絵（neutral.png）の顔あたり | `sora` |
| #ラウンジ | Mio | Mio の立ち絵の顔あたり | `mio` |
| #運営報告 | プロジェクトマネージャー | 好きな画像 | `manager` |

キャラが増えたら、同じように #ラウンジ に足します。キーは **キャラ ID**（アプリのキャラ管理の ID。英小文字）です。Sora・Mio 以外の ID だった場合は、PC で `atena doctor` を実行すると教えてくれます。

作り方（1 つずつ）:

1. チャンネル（#ラウンジ）を**長押し** → 「チャンネルを編集」（歯車）
2. 「連携サービス」→「ウェブフック」→「新しいウェブフック」
3. できた Webhook（「Spidey Bot」などの仮の名前）をタップ
4. 名前を `Sora` に変え、アイコンをタップして画像を選ぶ（「ファイル」→ iCloud Drive の立ち絵も選べます）→ 保存
5. 「ウェブフック URL をコピー」→ 下の 3. のメモに貼る

※ スマホアプリに「連携サービス」が見当たらない場合は、Safari で https://discord.com/app を開き、「デスクトップ用 Web サイトを表示」にすると同じ画面で作れます。

## 3. URL をメモに保存（Mac に渡すまで）

URL を知っている人はだれでもそのチャンネルに投稿できてしまうので、**このチャットや SNS には貼らない**でください。iPhone の「メモ」でロックをかけるか、パスワード管理アプリに保存します。メモはこの形にしておくと、PC でそのまま設定ファイルに貼れます:

```toml
room_master = "https://discord.com/api/webhooks/……"
manager = "https://discord.com/api/webhooks/……"
sora = "https://discord.com/api/webhooks/……"
mio = "https://discord.com/api/webhooks/……"
```

### iCloud Drive 経由で Mac に渡す（おすすめ・設定済み）

Atena は iCloud Drive の次のファイルを直接読むように設定済みです（`config/atena.toml`）。チャットや GitHub を通りません。

| ファイル（iCloud Drive/Atena/） | 中身 |
|------|------|
| `discord_webhooks.toml` | 上の 4 行 |
| `youtube.toml` | `api_key = "……"`（YouTube Data API のキー） |

- Mac で読めないときは、Finder の iCloud Drive → Atena フォルダを右クリック →「ダウンロード」（「Mac のストレージを最適化」がオンだと、ファイルが雲マークのまま中身が Mac に無いことがあります）。常に置いておくなら「ダウンロードしたままにする」
- ファイル名の最後が `.txt` になっていないか確認（エディタアプリが自動で付けることがあります）
- PC に向かったら `atena doctor` → `atena discord test`（各 Webhook からテスト投稿が 1 件ずつ出れば成功）

## 4. 通知の設定（おすすめ）

ラウンジは日中 2 時間おきに会話が流れるので、通知が多すぎないように:

- #ラウンジ: 長押し → 通知設定 →「@mentions のみ」（Atena はメンションを送らないので、実質通知なし。開いたときに読む）
- #運営報告: 「すべてのメッセージ」（毎朝 1 回の報告と、ラウンジ後の振り返りだけ）

## うまくいかないとき

| 症状 | 原因と対処 |
|------|-----------|
| `atena discord test` で「Discord の Webhook URL ではありません」 | URL の前後に空白や改行が入っている。貼り直す |
| テストで「⚠ ○○ は登録キャラの ID ではありません」 | キーがキャラ ID と違う。`atena character list` の ID に合わせる |
| 投稿は来るが名前が違う | Webhook の名前を Discord 側で直す（Atena 側の変更は不要） |
| Webhook を消してしまった | 作り直して、新しい URL に差し替える |
| URL を人に見られた | その Webhook を削除して作り直す（古い URL は使えなくなる） |
