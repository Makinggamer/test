# Atena project 要件定義書

各要件には ID を振り、実装モジュールと対応させています。
状態: ✅ Phase 1 実装済 / 🔜 後続フェーズ

---

## 1. キャラクター基盤（`atena/character.py`, `atena/agent.py`）

**目的**: 既存の Ollama キャラを流用し、人格・目標・自律度を持つタレントとして登録する。

| ID | 要件 | 状態 |
|----|------|------|
| CH-01 | キャラを TOML（`config/characters/<id>.toml`）で定義できる。項目: id, 名前, 使用モデル, 人格(persona), 話し方, 目標, 自律度レベル | ✅ |
| CH-02 | 既存の Ollama モデル（`ollama create` 済みのカスタムモデル）から SYSTEM プロンプトを取り込める（`/api/show`） | ✅ |
| CH-03 | Modelfile ファイルから取り込める | ✅ |
| CH-04 | Open WebUI 等のモデルエクスポート JSON から取り込める | ✅ |
| CH-05 | システムプロンプトは「共通憲章 + 人格 + 目標 + 現在のランキング + 関連記憶 + 関連ナレッジ」で毎回組み立てる。**オーナー個人情報・配信環境情報は一切含めない** | ✅ |
| CH-06 | キャラは企画案を JSON で自発的に提案できる（タイトル、種別、所要時間、収益見込みの理由、必要なシステム、コラボ相手） | ✅ |
| CH-07 | キャラの全出力はガーディアンを通過してから外に出る | ✅ |

## 2. プロジェクトマネージャー / タスク / 承認（`atena/manager.py`, `atena/tasks.py`）

| ID | 要件 | 状態 |
|----|------|------|
| PM-01 | オーナー・マネージャーがタスクを作成し、キャラ/役職に割り当てられる | ✅ |
| PM-02 | 日次サイクル: 各キャラの企画提案 → 企画審査（ネタ被り・規約） → 空き枠への仮配置 → 承認キュー投入 → 記憶整理 → ランキング更新 | ✅ |
| PM-03 | 自律度レベル(L0〜L3)に応じ、自動承認 / オーナー承認待ちを振り分ける。自動承認するレベルは設定で変更可 | ✅ |
| PM-04 | 「システムが必要」な企画はテクニカルディレクター宛タスクを自動生成 | ✅ |
| PM-05 | 状況レポート（予定、承認待ち、違反件数、ランキング、PC状態）を出力 | ✅ |

## 3. ガーディアン（意識統制官）（`atena/guardian.py`）

**目的**: キャラの発言が事務所ルールを守っているか検査し、違反を遮断する。

| ID | 要件 | 状態 |
|----|------|------|
| GD-01 | 差別・暴力的表現を NG ワード辞書（`config/ng_words.txt`、追記可能）で検出し **遮断** | ✅ |
| GD-02 | オーナー個人情報（`config/owner_secrets.toml` に登録、git管理外）を表記ゆれ（全角半角・空白）込みで検出し **遮断** | ✅ |
| GD-03 | 汎用個人情報（メール、電話番号、郵便番号、カード番号）を検出し **伏せ字化** | ✅ |
| GD-04 | 配信環境・内部情報（IPアドレス、MACアドレス、ファイルパス、ストリームキー/APIキー状の文字列、localhost:ポート、設定で登録した機材名・PC名等）を検出し **遮断** | ✅ |
| GD-05 | システムプロンプトの漏洩（プロンプト本文の長い一致）を検出し **遮断** | ✅ |
| GD-06 | 他キャラへの攻撃的発言（他キャラ名 + 敵対語）を検出し **遮断**（喧嘩防止） | ✅ |
| GD-07 | ルール通過後、判定用LLMで二次判定（JSON出力）。LLM障害時は設定に応じてフェイルクローズ（遮断） | ✅ |
| GD-08 | すべての違反を記録し、キャラ別の違反件数を集計。閾値超過でマネージャーにタスク起票 | ✅ |

| MM-02 | 視聴者ごとのプロフィール（表示名、初回/最終来訪、来訪回数、メモ）。視聴者IDはハッシュ化 | ✅ |

| MM-05 | LLM が使えない場合は機械的な切り詰めで圧縮（処理が止まらない） | ✅ |
| MM-06 | 視聴者数の上限を超えたら最終来訪が古い順に忘却 | ✅ |
| MM-07 | 保存前にガーディアンで個人情報を洗浄 | ✅ |
| MM-08 | 記憶使用量レポート | ✅ |

| RS-02 | 閾値（設定）と比較し ok / warn / critical を判定 | ✅ |
| RS-03 | 計測値を記録し履歴を参照できる | ✅ |
| SC-01 | 配信枠の提案・承認・却下・完了・キャンセル | ✅ |
| SC-02 | 制約チェック: 同時配信数上限、オーナーのPC使用時間帯（ブロック枠）、1日の総配信時間上限、VRAM見積もりがGPU総量を超えないこと | ✅ |
| SC-03 | 指定日の空き枠を自動提案 | ✅ |
| SC-04 | 配信直前プリフライト: その時点のPC状態が critical なら延期を推奨 | ✅ |
| SC-05 | 配信中に負荷を定期監視し、critical が続いたらキャラが締めの挨拶をして早めに終了 | ✅ |

## 7. ラウンジ（キャラ休憩所）（`atena/lounge.py`）

| ID | 要件 | 状態 |
|----|------|------|
| LG-01 | 複数キャラが話題に沿って会話するセッションを実行し、全文を保存 | ✅ |
| LG-02 | ルームマスターが話題を提示（最近のランキングやナレッジから） | ✅ |
| LG-03 | 各発言はガーディアン検査。違反発言は掲示せず、ルームマスターが警告を発し、違反を記録 | ✅ |
| LG-04 | セッション終了後、ルームマスターが有用情報を抽出してナレッジベースに登録 | ✅ |
| LG-05 | 面白い掛け合いを切り抜き候補として保存し、Markdown で台本出力 | ✅ |
| LG-06 | ナレッジはキャラのプロンプト組み立て時に関連するものが参照される | ✅ |
| LG-07 | 日次サイクルで1日1回ラウンジを開く（参加者は最大4人を抽選。配信中ロック・高負荷の間は見送り） | ✅ |
| LG-08 | 話題は「配信・収益の情報交換」と「誰かの好きなもの・仕事の雑談」の2種類。雑談回は題材の持ち主が主役で、自分の知識から話し、ほかのキャラは質問する（知ったかぶりしない）。最近扱っていない題材を優先。雑談の内容はナレッジ化しない | ✅ |
| LG-09 | 性格（口数）で発言の多さと長さが変わる。口数はキャラ定義の `talkativeness`（0〜1）、無ければ人格から推定（人格が変わるまでキャッシュ）。しばらく黙っているキャラには、話好きなキャラかルームマスターが話を振る。名前を呼んで質問されたキャラが次に答える | ✅ |
| LG-10 | 閲覧アプリ用に、セッション一覧と会話全文を API で提供 | ✅ |
| LG-12 | ラウンジが終わるたびにマネージャーが振り返り、各キャラにラウンジでの心がけ（60字以内・ガーディアン検査済み）と口数の微調整（1回±0.1、合計±0.3）を自動で反映。人格の見直し案は反映せず承認待ち（L3）へ。結果を Discord に運営メモとして投稿 | ✅ |
| LG-13 | 業務の話題は最近の話題と被らないように選ぶ | ✅ |
| LG-11 | ラウンジの会話をキャラごとの Discord Webhook（名前・アイコン）でリアルタイムに投稿。ガーディアンを通った発言のみ、規制分は本文を出さない、メンション無効、429 は待って再送、失敗してもラウンジは継続、あとから流し直し可 | ✅（実際の Discord では未検証） |

## 11.6 キャラの専門知識と場繋ぎ（`atena/expertise.py`, `atena/learning.py`）

| ID | 要件 | 状態 |
|----|------|------|
| EX-01 | キャラに「仕事・専門」「好きなもの」を設定（例: Mio は古書店員 → 古書・近代文学・本の修復） | ✅ |
| EX-02 | キャラごとの知識の記憶領域。情報源の優先順位（EX-12） | ✅ |
| EX-03 | Web から学ぶ: Wikipedia（検索・本文抜粋）と、キャラごとに登録したサイト / RSS。同じ記事は一度だけ。Web の文章は「資料」として扱い、資料内の指示に従わない | ✅ |
| EX-04 | コメントから学ぶ: 配信中のコメントを記録し、配信後に「教わった事実」を抽出。未確認として保存 | ✅ |
| EX-05 | 食い違いの解決: 判定用 LLM で矛盾を確認し、優先順位の高い情報を残す（低い方は格下げ）。同順位なら両方「要確認」で話題に使わない | ✅ |
| EX-06 | 未確認の知識を Web で照合し、裏付けがあれば確認済み（Web 扱い）、反証されれば格下げ | ✅ |
| EX-07 | 発言時、関連知識を「確かな情報 / 未確認」の区別付きでプロンプトに入れる。確かな情報は視聴者の話より優先しやんわり訂正、未確認は断定しない | ✅ |
| EX-08 | 容量管理（記憶マネージャー）: 格下げ30日・未確認7日で削除、話題ごとの上限超過は要約にまとめる、全体上限超過は優先度・使用回数の低い順に削除、上限90%でマネージャーにタスク起票 | ✅ |
| EX-09 | 場繋ぎ: コメントが一定時間途切れたら、好きなもの・専門の確かな知識を1つ選んで話し、問いかけでコメントを促す。同じ知識は同じ配信で繰り返さない。読み上げ中は割り込まない。連続しすぎたら間隔を広げる | ✅ |
| EX-10 | 知識・学習の検査: 内部情報・NG を含む知識は保存しない。個人情報は伏せ字 | ✅ |
| EX-11 | 一般 Web 検索（DuckDuckGo / SearXNG / Brave を設定で選択）で任意のサイトから学ぶ | ✅ |
| EX-12 | 情報源の段階: オーナー(5) > 参考資料(4: Wikipedia・登録サイト・信頼ドメイン) > Web(3: 一般サイト) > 要約(2) > コメント(1)。一般サイトの情報も別ドメインの2サイトで一致すれば参考資料に格上げ | ✅ |
| EX-13 | 任意サイト取得の安全策: 内部ネットワーク・ループバック等のアドレスに接続しない、robots.txt を守る、http/https のみ、サイズ上限、本文テキストのみ抽出 | ✅ |
| EX-14 | キャラの仕事・専門・好きなもの・学習サイトはデスクトップアプリの欄が正。アプリから同期する（Atena 側の編集はアプリの同期で上書きされる） | ✅（アプリ側実装待ち） |
