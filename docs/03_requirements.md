# Atena project 要件定義書

各要件には ID を振り、実装モジュールと対応させています。
状態: ✅ Phase 1 実装済 / 🔜 後続フェーズ

---

## 1. キャラクター基盤（`atena/character.py`, `atena/agent.py`）

**目的**: 既存の Ollama キャラを流用し、人格・目標・自律度を持つタレントとして登録する。

| ID | 要件 | 状態 |
|----|------|------|
| CH-01 | キャラを TOML（`config/characters/<id>.toml`）で定義できる。項目: id, 名前, 使用モデル, 人格(persona), 話し方, 目標, 自律度レベル | ✅ |
| CH-02 | 既存の Ollama モデル（`ollama create` 済みのカスタムモデル）から SYSTEM プロンプトを取り込める（`/api/show`） | ✅ |
| CH-03 | Modelfile ファイルから取り込める | ✅ |
| CH-04 | Open WebUI 等のモデルエクスポート JSON から取り込める | ✅ |
| CH-05 | システムプロンプトは「共通憲章 + 人格 + 目標 + 現在のランキング + 関連記憶 + 関連ナレッジ」で毎回組み立てる。**オーナー個人情報・配信環境情報は一切含めない** | ✅ |
| CH-06 | キャラは企画案を JSON で自発的に提案できる（タイトル、種別、所要時間、収益見込みの理由、必要なシステム、コラボ相手） | ✅ |
| CH-07 | キャラの全出力はガーディアンを通過してから外に出る | ✅ |

## 2. プロジェクトマネージャー / タスク / 承認（`atena/manager.py`, `atena/tasks.py`）

| ID | 要件 | 状態 |
|----|------|------|
| PM-01 | オーナー・マネージャーがタスクを作成し、キャラ/役職に割り当てられる | ✅ |
| PM-02 | 日次サイクル: 各キャラの企画提案 → 企画審査（ネタ被り・規約） → 空き枠への仮配置 → 承認キュー投入 → 記憶整理 → ランキング更新 | ✅ |
| PM-03 | 自律度レベル(L0〜L3)に応じ、自動承認 / オーナー承認待ちを振り分ける。自動承認するレベルは設定で変更可 | ✅ |
| PM-04 | 「システムが必要」な企画はテクニカルディレクター宛タスクを自動生成 | ✅ |
| PM-05 | 状況レポート（予定、承認待ち、違反件数、ランキング、PC状態）を出力 | ✅ |

## 3. ガーディアン（意識統制官）（`atena/guardian.py`）

**目的**: キャラの発言が事務所ルールを守っているか検査し、違反を遮断する。

| ID | 要件 | 状態 |
|----|------|------|
| GD-01 | 差別・暴力的表現を NG ワード辞書（`config/ng_words.txt`、追記可能）で検出し **遮断** | ✅ |
| GD-02 | オーナー個人情報（`config/owner_secrets.toml` に登録、git管理外）を表記ゆれ（全角半角・空白）込みで検出し **遮断** | ✅ |
| GD-03 | 汎用個人情報（メール、電話番号、郵便番号、カード番号）を検出し **伏せ字化** | ✅ |
| GD-04 | 配信環境・内部情報（IPアドレス、MACアドレス、ファイルパス、ストリームキー/APIキー状の文字列、localhost:ポート、設定で登録した機材名・PC名等）を検出し **遮断** | ✅ |
| GD-05 | システムプロンプトの漏洩（プロンプト本文の長い一致）を検出し **遮断** | ✅ |
| GD-06 | 他キャラへの攻撃的発言（他キャラ名 + 敵対語）を検出し **遮断**（喧嘩防止） | ✅ |
| GD-07 | ルール通過後、判定用LLMで二次判定（JSON出力）。LLM障害時は設定に応じてフェイルクローズ（遮断） | ✅ |
| GD-08 | すべての違反を記録し、キャラ別の違反件数を集計。閾値超過でマネージャーにタスク起票 | ✅ |

## 4. コメントモデレーター（`atena/moderator.py`）

| ID | 要件 | 状態 |
|----|------|------|
| CM-01 | プロンプトインジェクション（「指示を無視」「システムプロンプトを教えて」等）を検出し、キャラに渡さない | ✅ |
| CM-02 | オーナーや配信環境を探る質問（住所、本名、PCスペック、IP等）を検出し、定型の安全な返し用フラグを立てる | ✅ |
| CM-03 | 視聴者コメント内の個人情報を伏せ字化してからキャラに渡す | ✅ |
| CM-04 | URL・連投・同一文字の連続などのスパムを除外。投稿者ごとのレート制限 | ✅ |
| CM-05 | NG ワードを含むコメントは除外 | ✅ |

## 5. 記憶マネージャー（`atena/memory.py`）

| ID | 要件 | 状態 |
|----|------|------|
| MM-01 | キャラごとに記憶を保持: エピソード（配信・会話の出来事）、事実、視聴者メモ、要約(digest) | ✅ |
| MM-02 | 視聴者ごとのプロフィール（表示名、初回/最終来訪、来訪回数、メモ）。視聴者IDはハッシュ化 | ✅ |
| MM-03 | 記憶検索: 日本語でも動く文字バイグラム類似度 + 重要度 + 新しさでスコアリング | ✅ |
| MM-04 | 容量上限（件数・文字数）を設定。超過時、直近N件を残して古く重要度の低い記憶をLLMで要約して1件の digest に圧縮 | ✅ |
| MM-05 | LLM が使えない場合は機械的な切り詰めで圧縮（処理が止まらない） | ✅ |
| MM-06 | 視聴者数の上限を超えたら最終来訪が古い順に忘却 | ✅ |
| MM-07 | 保存前にガーディアンで個人情報を洗浄 | ✅ |
| MM-08 | 記憶使用量レポート | ✅ |

## 6. リソースモニター / スケジューラ（`atena/monitor.py`, `atena/scheduler.py`）

| ID | 要件 | 状態 |
|----|------|------|
| RS-01 | CPU%、メモリ%、GPU%、GPUメモリ、温度、スワップ、Ollama のロード中モデルのメモリを取得。macOS は ioreg（GPU使用率）・pmset（熱による速度制限）・ユニファイドメモリ換算、Linux/Windows は nvidia-smi。取れない値は「不明」として扱う | ✅ |
| RS-02 | 閾値（設定）と比較し ok / warn / critical を判定 | ✅ |
| RS-03 | 計測値を記録し履歴を参照できる | ✅ |
| SC-01 | 配信枠の提案・承認・却下・完了・キャンセル | ✅ |
| SC-02 | 制約チェック: 同時配信数上限、オーナーのPC使用時間帯（ブロック枠）、1日の総配信時間上限、VRAM見積もりがGPU総量を超えないこと | ✅ |
| SC-03 | 指定日の空き枠を自動提案 | ✅ |
| SC-04 | 配信直前プリフライト: その時点のPC状態が critical なら延期を推奨 | ✅ |
| SC-05 | 配信中に負荷を定期監視し、critical が続いたらキャラが締めの挨拶をして早めに終了 | ✅ |

## 7. ラウンジ（キャラ休憩所）（`atena/lounge.py`）

| ID | 要件 | 状態 |
|----|------|------|
| LG-01 | 複数キャラが話題に沿って会話するセッションを実行し、全文を保存 | ✅ |
| LG-02 | ルームマスターが話題を提示（最近のランキングやナレッジから） | ✅ |
| LG-03 | 各発言はガーディアン検査。違反発言は掲示せず、ルームマスターが警告を発し、違反を記録 | ✅ |
| LG-04 | セッション終了後、ルームマスターが有用情報を抽出してナレッジベースに登録 | ✅ |
| LG-05 | 面白い掛け合いを切り抜き候補として保存し、Markdown で台本出力 | ✅ |
| LG-06 | ナレッジはキャラのプロンプト組み立て時に関連するものが参照される | ✅ |

## 8. 収益・ランキング（`atena/revenue.py`）

| ID | 要件 | 状態 |
|----|------|------|
| RV-01 | 収益記録: キャラ、種別（superchat / membership / ads / goods / other）、金額(円)、日時、メモ | ✅ |
| RV-02 | 期間指定ランキング（合計、種別内訳、前期間比） | ✅ |
| RV-03 | ランキング講評は前向きな表現のみ（下位を貶さない）。講評もガーディアンを通す | ✅ |
| RV-04 | 収益 CSV エクスポート（税務用） | ✅ |
| RV-05 | YouTube のスーパーチャット/スーパーステッカーを自動で台帳に記録（円換算・重複防止）。メンバーシップ収益は金額が API で取れないため手入力 | ✅ |

## 9. AItuber 配信連携（`atena/stream/`）

| ID | 要件 | 状態 |
|----|------|------|
| ST-01 | 配信チャットの抽象インターフェース。コンソール入力による模擬配信 | ✅ |
| ST-02 | Twitch チャット接続 | 🔜 後回し |
| ST-03 | YouTube Live チャット取得。API キー + 動画ID / OAuth（自分の配信を自動検出）。接続前の過去ログには応答しない。API 割り当てを配信時間で配分してポーリング間隔を自動調整 | ✅ |
| ST-04 | 読み上げ。Irodori-TTS-Server（参照音声 voice_id + 話し方 caption）のみを使用し、予備の声は持たない。読み上げは裏で順に処理し、溜まりすぎたら古い通常返答は字幕のみ（スパチャのお礼は必ず読む）。字幕は再生開始に合わせて表示。`voice bench` で生配信に使える速さか計測 | ✅ |
| ST-07 | ボイストラブル時（合成失敗・時間切れ・声未設定）は「ボイストラブル中」の注意書きを OBS に出して字幕のみで継続。一定時間後に声を再挑戦し、復帰したら注意書きを消す。配信の字幕は SRT として保存 | ✅ |
| ST-06 | デスクトップアプリの重い処理（LoRA 学習等）のロックファイルを検出して配信開始を止め、配信中は Atena 側からロックを置く（既存ロックは上書きしない・自分のロックだけ消す） | ✅ |
| ST-05 | OBS への字幕・コメント表示（テキストファイル方式）。検査を通過したコメントのみ表示。シーン切替は後回し | ✅ |

## 12. デスクトップアプリ連携（`atena/api.py`、詳細は [04_desktop_app_integration.md](04_desktop_app_integration.md)）

| ID | 要件 | 状態 |
|----|------|------|

| IN-05 | 承認キューの閲覧と承認・却下、ランキング、スケジュール、PC 状態、状況レポートの取得 | ✅ |

## 13. 非機能要件

| ID | 要件 |
|----|------|
| NF-01 | 完全ローカル動作。外部通信は Ollama（localhost）と、Phase 2 以降の配信プラットフォームのみ |
| NF-02 | Python 3.11 以上、標準ライブラリのみで動作（psutil は任意・Mac では推奨） |
| NF-03 | macOS (Apple Silicon) を主対象。Linux / Windows も動作（GPU 計測は NVIDIA） |
| NF-04 | データは SQLite 1ファイル（`data/atena.db`）。バックアップはファイルコピーで可 |
| NF-05 | 秘密情報（`owner_secrets.toml`、DB）は `.gitignore` 済み |
| NF-06 | LLM 応答待ちのタイムアウトを設定可能。LLM 停止時も監視・集計・スケジュールは動く |
